# 사이트 기획: 목적과 원칙

이 문서는 `site/`에 만들 웹 앱의 목적과, 기획하면서 정한 원칙을 기록합니다. 결정이 바뀌면 이 문서를 고치고, 바뀐 이유를 "결정 기록"에 남깁니다.

## 목적

Svelte를 써 본 개발자가 단계별 인터랙티브 시각화를 따라가면, Svelte 5의 내부 동작 원리를 이해하게 되는 한국어 학습 경로를 만듭니다. Svelte 커뮤니티에 기여하는 것이 목표입니다.

## 독자

- **출발점**: Svelte를 써 본 개발자입니다. 공식 튜토리얼 수준의 사용법(`$state`, `$derived`, `$props`, 이벤트, `{#if}`, `{#each}` 등)은 안다고 가정합니다. 사용법 설명은 공식 문서로 넘깁니다.
- **언어**: 한국어를 먼저 씁니다. 영어는 나중에 추가할 수 있도록 구조만 염두에 둡니다.

## 도달 목표

경로를 끝까지 따라간 독자는 다음을 할 수 있어야 합니다.

| 도달 목표                                                                                                               | 대응하는 커리큘럼 단계              |
| ----------------------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| 컴포넌트의 컴파일 결과를 보고, 각 줄이 왜 생기는지 설명할 수 있습니다.                                                  | 1단계 컴파일 결과 관찰              |
| 상태 하나를 바꿨을 때 어떤 derived와 effect가 어떤 순서로 다시 실행되고, DOM의 어느 부분이 바뀌는지 추적할 수 있습니다. | 2단계 signal 시스템, 3단계 DOM 계층 |
| `.svelte` 파일이 파싱, 분석, 변환을 거쳐 코드가 되는 과정을 설명할 수 있습니다.                                         | 4단계 컴파일러                      |
| 코드의 한 줄이 왜 그렇게 쓰였는지 git 이력과 PR에서 찾아낼 수 있고, 나아가 이슈나 PR로 기여할 수 있습니다.              | 5단계 코드 고고학                   |

## 원칙

1. **학습 경로가 곧 공부 순서입니다.** 작성자는 경로의 순서대로 공부하면서 첫 번째 독자로서 경로를 검증합니다(dogfooding). 그래서 커리큘럼의 질문 순서도 독자 기준으로 정합니다.
2. **공부 단위가 곧 공개 단위입니다.** 한 구간을 공부하고, 노트(`notes/`)와 곁가지 기록(`log/tangents/`)을 정리하고, 그것을 경로의 한 장으로 다듬어 공개하는 흐름을 반복합니다.
3. **줄글보다 실행 흐름의 시각화가 중심입니다.** 코드의 현재 실행 줄과 그 결과(DOM, 노드 순서, 값, signal 그래프 등)를 함께 보여 주고, 독자가 단계를 넘기며 따라가게 합니다. 구체적인 인터랙션 방식은 따로 정합니다.
4. **곁가지 질문도 콘텐츠입니다.** 공부하면서 떠오른 자잘한 질문과 답을 본문과 연결해서 함께 싣습니다.
5. **예측하고, 틀리고, 확인한 과정을 남깁니다.** 결론만 정리하지 않고, 처음 세운 가설이 어떻게 틀렸고 어떤 실험과 코드로 확인했는지를 보여 줍니다. 이것이 다른 해설 자료와 구별되는 점입니다.
6. **모든 주장에는 근거를 붙입니다.** 근거는 `svelte@5.0.0`의 소스 코드 위치나 실험 결과입니다.
7. **질문을 먼저 던지고, 해설은 독자가 고민한 뒤에 공개합니다.** 독자가 스스로 충분히 생각해 볼 수 있도록 유도 질문을 먼저 보여 주고, 공부해서 알아낸 해설은 독자가 원할 때 펼쳐 보게 합니다.
8. **경로는 대략적으로 정하고, 공부하면서 다듬습니다.** 처음부터 완벽하게 구성하려고 하지 않습니다. 공부하다 보면 장을 나누거나 질문을 옮기게 되므로, 그때그때 고칩니다.

## 작성 방식

- 튜터가 유도 질문을 던지고, 학습자가 채팅으로 대강 답합니다. 튜터는 그 답을 코드와 실험으로 확인하고 다듬어서, **유도 질문과 해설의 쌍**을 `notes/`에 기록합니다. 이 쌍이 그대로 사이트에서 "질문 → 고민 → 해설 공개"의 원재료가 됩니다.
- 문체는 학습자가 진행하면서 지시합니다. 지시가 나오면 `CLAUDE.md`의 "노트 작성 방식" 절에 기록합니다.

## 컨셉: 『Svelte 대백과』

사이트를 열면 어두운 서재 한가운데에 **고서풍의 두꺼운 백과사전 한 권**이 중심 오브젝트로 놓여 있습니다. 각 장(chapter)은 이 책의 한 펼침면입니다. 첫인상은 Stripe Press(https://press.stripe.com/)처럼 책이 화면 속의 물리적인 사물로 느껴지는 3D 감각을 목표로 합니다. 똑같이 만드는 것이 아니라, 책 자체가 내비게이션이 되고 책 말고는 거의 아무것도 없는 절제를 참고합니다.

| 사이트의 구조 | 책에서의 모습 |
|---|---|
| 첫 화면 | 어두운 서재에 놓인 가죽 장정의 책 한 권. 금박 제목. 마우스를 따라 아주 살짝 기울어짐 |
| 학습 경로(1~5단계) | 책등의 다섯 마디. 책을 펼치면 첫 장이 목차 |
| 한 장 | 펼친 책의 양면. 왼쪽 면은 본문, 오른쪽 면은 도판(코드와 시각화) |
| 유도 질문 | 번호가 붙은 문항 |
| 해설 공개 | 본문에 끼워진 접힌 쪽지를 펼침 |
| 근거 | 각주 |
| 곁가지 질문 | 난외주 |
| 처음 세운 가설 | 연필로 적은 메모 |
| 진행 상황 | 가름끈 |

- 애니메이션은 Emil Kowalski의 skill(`.claude/skills/emil-design-eng`, `animate` 등)의 기준을 따릅니다. 자주 반복되는 동작(노드 탐색 버튼, 쪽지 펼치기)은 짧고 가볍게, 드물게 일어나는 동작(책 표지 펼치기)은 충분히 길고 공들여 만듭니다.

## 화면 구성

- **시제품 장**: 1-2장(노드를 찾아가는 방법)으로 사이트의 한 장을 먼저 만들어 봅니다. 유도 질문, 틀린 예측, 곁가지, playground에 넣기 좋은 예제, 단계별 시각화에 넣기 좋은 장면이 모두 들어 있기 때문입니다.
- **페이지 골격: 2단 스크롤 연동**. 왼쪽에는 유도 질문과 해설이 세로로 이어지고, 오른쪽에는 코드와 시각화 패널이 고정되어 있습니다. 왼쪽을 읽어 나가면 오른쪽 패널의 강조된 줄과 그림이 함께 바뀝니다.
- **진행 방식: 해설을 펼쳐야 다음이 열림**. 질문 아래는 잠겨 있고, 독자가 "생각해 봤어요"를 눌러 해설을 펼치면 다음 질문이 나타나고 오른쪽 패널도 다음 장면으로 넘어갑니다. 독자가 이해했을 때 다음 코드 부분으로 넘어가게 하고, 다음 질문이 앞 질문의 답을 미리 알려 주는 것을 막습니다.

## 기술 스택

| 영역 | 선택 |
|---|---|
| 사이트 | SvelteKit 3 + 최신 Svelte 5, `adapter-static`으로 정적 빌드 |
| 콘텐츠 | mdsvex(`.svx`). 마크다운 안에서 장 컴포넌트를 씁니다. |
| 코드 강조 | Shiki. 빌드할 때 학습 자료 파일을 읽어서 미리 강조합니다. |
| playground | 사이트와 별도로 `svelte@5.0.0`을 npm 별칭으로 설치해서 브라우저에서 컴파일할 예정입니다(아직 만들지 않음). |

## 시제품 상태

- 첫 화면(`/`): 3D 책, 표지 열기, 목차. 1-2장(`/learn/1-2`): 펼친 책 양면, 접힌 쪽지, 각주, 연필 메모, 코드 도판, 노드 탐색 도판. Q1.3의 유도 질문 1~3번까지 들어 있습니다.
- 진행 상황과 다음 할 일은 루트의 `PROGRESS.md` "현재 상태와 다음 할 일" 절에 있습니다.

## 학습 경로 (초안)

1단계의 경로는 `curriculum/01-compiled-output.md`의 "학습 경로" 표에 있습니다. 직접 짠 바닐라 카운터와 Svelte의 컴파일 결과를 비교하는 것에서 출발하고, 그 비교에서 나오는 여섯 가지 차이(노드 만들기, 찾기, 문서에 넣기, 값 갱신, 상태 선언, 이벤트 연결)를 한 장씩 다룬 뒤, 다른 출력 모드로 마무리합니다. 2단계부터는 해당 단계를 시작할 때 같은 방식으로 정합니다.

## 범위

- **Svelte 버전**: `svelte@5.0.0`만 다룹니다. 최신 버전과의 차이는 다루지 않습니다.
- **위치**: 이 레포의 `site/` 폴더에 둡니다. 노트, 곁가지 기록, 실험 파일, 컴파일 결과를 빌드할 때 그대로 가져다 씁니다.

## 아직 정하지 않은 것

- 경로의 한 장이 어떤 구성 요소로 이루어지는지
- 노트의 문체
- 인터랙티브 시각화의 구체적인 방식. 페이지 골격은 정했고(아래 "화면 구성"), 진행 방식도 정했고, 오른쪽 패널의 장면 종류와 애니메이션은 아직 정하지 않았습니다.
- 글 곳곳에 넣을 코드 playground의 구현 방식. 독자가 예제를 직접 고치면 `svelte@5.0.0`의 컴파일 결과와 실행 결과, DOM 변경 기록이 바로 바뀌는 형태를 원합니다. 공식 사이트의 playground처럼 브라우저에서 컴파일러를 실행하는 방식을 검토합니다.
- 배포할 호스팅 위치
